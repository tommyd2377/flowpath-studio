## Experience to deliver

The visitor should feel that they are working with a responsive, intelligent visual workspace. Voice is the primary interaction when enabled; typing and ordinary controls use the same underlying behavior. Content appears in response to the visitor, except the introduction and content explicitly selected by the publisher for the opening.

This exact sequence must work in one session:

1. “Show me the address.” An address object appears.
2. “Show me the email too.” The address remains and an email object is added.
3. “Open this photo from that collection.” The selected photo opens with its correct collection context; existing objects remain unless the visitor asked to replace them.
4. “Show a map too.” A supported location/map view is added beside the other objects, with an honest fallback when coordinates or the relevant capability are unavailable.
5. “Make that photo bigger,” “the one on the left,” and “close the map but keep the photo” resolve to actual current objects, or ask a brief clarification if ambiguous.
6. “I'm done with this photo.” It closes or returns to its actual origin; the other objects, their state, and relevant browsing position remain.

Desktop can arrange several objects together. Mobile can stack or page them with clear controls; an object being offscreen must not mean it was closed.

## Required architecture and behavior

1. **Introduce independently addressable workspace objects.** Separate registered component type, stable content reference, and unique instance ID. Support several instances of the same type and mixed information/photo/map/detail/comparison objects. Evolve the current `component.id === component.type` restriction through validated compatibility rather than merely deleting its check. Keep a bounded session workspace with per-object state, selection, focus, disclosure, origin, and layout intent. One selected/focused object must not erase the others. Define sensible capacity handling; never silently evict content the visitor asked to retain.

2. **Use validated operations on the workspace.** Provide deterministic add, update, focus, expand/collapse, close, and explicit replace/reset behavior through a shared reducer or equivalent existing pattern. Both manual controls and model/voice requests invoke it. Validate instance IDs, published entity/fact/media/capability references, external-result references, revisions, and limits. Apply multi-object requests as one coherent bounded operation batch rather than requiring a paid model round trip per object. Make duplicate requests idempotent, reject stale/conflicting batches, cancel stale model work after manual interaction, and preserve the last useful view on failure. Models request semantic intent; runtime code owns exact layout, animation, markup, URLs, and action routing.

3. **Connect the graph to presentation.** Use assignment 1's bounded retrieval/projection boundary. Select relevant facts, relationships, media, and qualified values for the visitor's intent, including standalone contact/location facts. Keep graph IDs distinct from component instances and session search IDs. Existing documents should support several appropriate presentations without ingestion generating page layouts. Do not expose raw source artifacts, disputed unpublished assertions, or unsupported certainty. A missing fact or relation should yield an honest narrower view or clarification.

4. **Make screen awareness describe the actual workspace.** Extend the current structural screen context to report stable object IDs, content references, useful names from validated records, object order, relative position, active focus, selection, expanded sections, and supported controls. Distinguish open, mounted, viewport-visible, partially visible, fully visible, and hidden/obscured by runtime overlays where relevant. Track the object's scroll container as well as page scroll. Visibility should come from actual browser geometry/state, not the plan the model wished to display. Keep payloads bounded, revisioned, deduplicated, and updated at meaningful interaction/layout changes, without continuous paid calls or noisy loops. Resolve “that,” “left,” “second,” and “the photo from that collection” against the current acknowledged scene, not stale ordinal guesses.

5. **Integrate the current voice and typing paths.** Studio now uses GPT-Live application adapters; older task discussions of voice transport are historical. Extend those adapters and existing browser acknowledgments. Distinguish accepted, applied, failed, and cancelled requests. The assistant must not say an object is displayed before a successful browser result. Speech can begin useful factual content while work proceeds, but no misleading navigation claims or spoken tool preambles. A failed/hidden-tab/expired request must terminate cleanly, preserve the view, and not trigger automatic paid retries. Keep existing playback, manual interruption, inactivity, quota, and publication controls. Stay out of the shared GPT-Live transport core and the news app.

6. **Unify catalog and photo interaction.** Photos, albums, entities, site sections, contact facts, and relevant information belong to one discoverable content experience when requested. They can use different semantic components; do not flatten every item into a generic card or force albums to become fake product entities. Preserve album order, contextual links, credits, alt text, actual-versus-example labels, and current-publication image authorization. Existing external search can coexist with published content; bring its accepted results/maps into the same workspace interaction model while keeping external provenance, opt-in settings, and noncanonical status explicit. External results never silently modify the publisher graph.

7. **Complete the visual and motion system.** Build on the existing free Motion primitives, chat dock choreography, FocusStage, FocusSurface, DisclosureStack, ReturnAnchor, and VoiceFocusBridge. An overview item should smoothly move and expand into a readable focus surface, reveal useful text/facts/images/relationships progressively, and return gracefully to its origin. Background content can recede during focused reading without destroying the multi-object workspace. Preserve scroll, filters, selection, and nested origins. Add richer multimodal cards, related context, and meaningful comparisons where the existing schema supports them. Use restrained text/line reveals; full accessible text must remain available without waiting through a simulated typing sequence. Prioritize continuity, clear hierarchy, interruption, and responsive geometry over gratuitous motion. No paid Motion+ dependency or second animation runtime is needed for this assignment. Annotated image regions and diagrams require real reviewed data/contracts; do not fabricate them to decorate the demo.

8. **Deliver the publisher's basic style choices.** Build a small coherent set of three layout presets and three accessible color palettes using the existing design tokens/variant system; these satisfy the requested initial range of three to five. They must work across the same semantic content and workspace operations, in preview and publication, with sensible defaults for existing sites. Use the recovered FlowPath assets tastefully within the already established Studio brand. Keep publisher identity prominent and avoid incidental renaming of internal code/package names. This is not a separate redesign of every Studio screen.

9. **Implement the three-point spoken greeting.** Let the publisher choose three pieces of approved information during greeting setup, with clear optional empty slots and a preview. Prefer stable reviewed-content references where available; publisher-authored information must go through the appropriate draft/publication validation. Voice supplies concise natural wording and transitions around the selected points and tone, without filling factual gaps. Support deterministic/offline preview and a useful fallback; do not add a new paid call solely to preview text. Persist through Save/Publish, validate/prune invalid selections during content updates and Undo, and respect visitor-speaks-first. Spoken selections and visually featured opening content are related settings, not automatically the same thing. Preserve existing greeting choices through migration/defaults.

10. **Keep the site usable without AI.** Default initial rendering must not quietly include every catalog item, footer contact section, or album below the fold. Offer an unobtrusive explicit way to browse approved information with ordinary controls, including after voice/chat failure or exhausted allowance. Use the same objects and content references in this fallback. Preserve keyboard operation, predictable focus return, visible close/back controls, semantic reading order, readable contrast, zoom, and reduced motion. Nonmodal workspace focus must not become an inappropriate focus trap; modal photo viewing still needs proper modal behavior.
