# Website Motion before/after evidence — 19 September 2026

The actual cake-shop publication was visually inspected in the Codex in-app browser, including opening animation frames, the mobile menu, a cake detail, Escape and focus return. Its Showcase / Subtle appearance and saved publication were not changed. The opening headline now travels 54 px on desktop and 37.8 px on mobile, with independently timed copy and a finite image-frame reveal.

The table links full short recordings of each opening and scroll sequence. Each synthetic publisher runs all three templates at 1440×1000 and 390×844. Menu and services/portfolio fixtures contain synthetic illustrations; guide and travel fixtures intentionally have no images. The actual cake-shop recordings are read-only visits to localhost:3220. They block non-GET requests and external hosts. Fixture setup and draft/publication checks use only the isolated offline demo on localhost:3225.

## Reading the measurements

[Comparison data](comparison.json) summarizes the per-frame observations beside each recording. Headline displacement is the maximum observed computed translation, including ancestors, rather than the configured animation value. Video startup/font timing varies, so maximum observed values can be lower than a configured starting value. Each after sequence asserts sustained visible movement, independently timed title/copy, section movement, no horizontal overflow and fully readable settled content.

Scroll-only CLS is recorded separately from the complete cold-load CLS. Some earlier guide/travel baselines predate the separate scroll counter; their missing value is unavailable, not zero. Initial font/layout shifts and main-thread long tasks are reported rather than attributed to animation. These are bounded local Chromium observations with recording overhead, not physical-device or low-end-device measurements.

Off and reduced motion, live preference changes, keyboard/hover feedback, nested Studio scrolling, dynamic expansion, fast scrolling and visibility interruption have additional assertions in `tests/browser/website-motion.spec.ts`. A React commit probe checks that eight scroll actions do not cause React renders after the page settles. Existing website suites cover native FAQ/menu behavior, details, focus return, image failure, absent observers, no JavaScript, larger text, narrow/tablet/wide layouts and preservation when the assistant is opened and closed using the offline fixture.

All 26 after sequences finished with zero measured horizontal overflow, zero unreadable targets and zero scroll-only CLS. The 24 synthetic sequences had no >50 ms long tasks; scrolling frame intervals had a 16.7 ms median and 17.4–23.3 ms 95th percentiles. The actual desktop capture recorded one 52 ms long task over the full load/scroll recording, with a 17 ms scrolling p95; mobile recorded no long task and a 17.6 ms scrolling p95. Cold-load CLS was not zero: the synthetic maximum was 0.04644; the actual desktop/mobile values were 0.00067 / 0.01855. These measurements do not isolate fonts or unrelated application work.

## Final verification

- Motion suite: seven synthetic scenarios passed, covering 24 recordings plus Off/reduced motion, live gesture disabling, nested scrolling, dynamic expansion, visibility cleanup and zero React commits across eight settled scroll actions. The separately selected read-only actual-site scenario passed for both widths.
- Existing website design suite: all eight scenarios passed. Seven passed together; the image-depth check passed on a focused rerun after changing it to observe computed transforms, since native browser animations do not update the inline `style` attribute on each frame.
- Hero suite: all three image-proportion scenarios passed across all templates at 390, 1440 and 1920 px.
- Existing template suite: seven relevant scenarios passed, including all three fixtures in desktop/mobile/embedded previews, Branding/publication separation, palettes, sparse and 100-entry content, and paginated detail/reference validation. Source ingestion and the separate assistant-information scenario were outside this run.
- Lint, typecheck, all 24 rendering tests, independent packed-package verification and the production build passed under Node 24.6.0.
- The broad server run had 590 passing tests and one unrelated failure: `tests/gpt-live.test.ts` requires byte-identical sibling runtime files, while concurrent work added a comment in `lib/gpt-live/protocol.ts` that the FlowPath sibling lacks. That other task's files were preserved. Consequently the aggregate `npm run check` is **not** reported as passing; its remaining stages were run separately as listed above.

The in-app browser pass confirmed real intermediate title/frame/section states and settled content, mobile anchor navigation, detail opening, Escape and focus return. Synthetic browser coverage also includes missing observers, no JavaScript, failed/slow images, native questions, 320/768/1920 px widths and website continuity around the offline assistant. This does not claim live voice/provider or physical Safari/iOS testing. No paid/model requests, customer publication, deployment or signed-in browser testing was performed.
