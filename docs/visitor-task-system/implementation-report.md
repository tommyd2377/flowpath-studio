The source-of-truth publication separates collection containment, explicit membership, derived membership and semantic relationships. Shared record IDs carry one set of assertions across branches. Descendant/union results deduplicate records; breadcrumbs retain the chosen containment path. Derived collections validate dependency cycles before materialization. A grouping collection cannot silently contain explicit records.

Public v2 pages carry a publication reference, not the legacy directory or 10,000 records. Published media stays in its existing separate, bounded, current-authorized media library. The v1 query adapter and explicit v2 migration project reviewed photos/albums as photo records and gallery collections; cross-listed photos share one canonical record, original asset IDs remain authorization references, and namespace collisions do not replace entity IDs. Query cards reuse existing media components, including illustrative-example labeling. Bulk import does not infer photo identities or lift the 100-asset media limit. Registered publisher HTTPS links survive migration as bounded reviewed metadata; the registry can retrieve/present them, and only the visitor follows a link.

## Query and capability contracts

`PublicationSpace`, `QuerySpec`, `QueryPatch`, `QueryResult`, selection, artifact and task payloads declare version 2; capability descriptors declare version 1. Original v1 publications remain readable and capped at 100 entities.

A query contains a publication revision, scope (`direct`, `descendants`, or explicit union with chosen path), typed expression tree, search text, preferences, sort keys, `asOf` and an IANA time zone. Nodes have stable IDs so replacing an author/indoor/date node preserves unrelated constraints. Undo retains 20 revisions; fork creates another independent query. Up to eight queries and 100 selected canonical references share a visitor session.

Expressions support AND/OR/NOT, field predicates, explicit state predicates and directed relationships. Validation bounds depth to four, total nodes to 64, leaves to 24 and relationship hops to two. Reviewed descriptors own type, cardinality, supported operations, applicable record types, aliases, units/currency/basis, coverage and time semantics. No publisher vocabulary is embedded in the evaluator. Dates accept date-only values or explicit-offset instants; date-only legacy values retain UTC interpretation. Currency/unit/basis mismatches reject rather than convert implicitly. Unknown under NOT remains unknown; false is distinct from missing; conflicting, conditional and expired assertions remain distinguishable. Hard constraints run before preferences. Zero results return explicit alternative counts without applying relaxation.

Result pages default to 24 records, have stable result-set IDs and `R` codes independent of layout, and bind cursors to session, publication, query scope/revision and sort. Visible ordinals require the exact current scene revision and ordered, visible canonical IDs. Completion ACKs are distinct from ongoing viewport observations: `lib/use-task-viewport.ts` invalidates on movement and debounces settled updates; the task route validates them and `VisitorTaskStore` stores them under `scene-<sessionId>` with a separate CAS revision. Unchanged observations are suppressed. Scroll/resize writes never repeat completion receipts or conflict with task-state revisions. Both model channels receive the current bounded scene, and evidence depending on a visible reference becomes invalid when its scene changes. Manual changes cancel outstanding model work and invalidate stale dependencies. Home closes pending work while preserving the cart, selection and saved artifacts.

The registry includes schema/collection discovery, query create/patch/activate/page/close, record lookup/search/filter/detail, reference resolution, selection/comparison, typed presentation, clarification, research/maps, retained web/image presentation, artifacts and demo actions. Every capability validates input and output. Dependent inputs bind a retained handle's exact type and current authority. Results are stored server-side with session/publication/generation/revision/expiry dependencies. Browser descriptions never substitute for evidence. A read produces a result receipt without changing the persisted presentation; a displayed operation needs the exact settled browser ACK after its requested detail/comparison/research/artifact/action panel is brought into view; comparisons and details acknowledge their own visible canonical records; synthetic external effects use adapter receipts. Task metadata and operation reservations are persisted before effects. Failure retains completed independent work; uncertain commits enter reconciliation instead of automatic retry.

Both channel bridges use fresh context each model round, four tool executions plus a final response (five model calls), a 120-second task deadline and a per-task capability ceiling of 16. Capability calls and provider-reported input/output tokens are recorded in task state. Composite work does not start hidden unmetered provider substeps. `task.clarify` displays a bounded question/options and records `needsClarification` after its ACK. A task session is initialized before conversational work so later turns can reuse read-only evidence even when no result was displayed.

## Import, migration and rollback

Existing source review still uses bounded v1 knowledge artifacts and provenance. Documents, tables and websites can propose nested collections/content blocks; a source heading is not approval to publish. Publishers edit names, parents, memberships, aliases and facts, inspect existing source provenance, Apply, then Publish. A paragraph remains a record detail block unless the source/review establishes a distinct record.

For a reviewed existing catalog, **Knowledge → Review source knowledge as collections** creates a v2 review without changing the publication. For bulk imports, **Knowledge → Import collection file (.jsonl)** streams a first metadata line followed by canonical batches. Use the generator for an exact valid format:

```sh
source "$HOME/.nvm/nvm.sh"
nvm use 24
node --import tsx scripts/generate-visitor-task-fixture.ts --records 10000 --vocabulary 0 --output /private/tmp/flowpath-visitor-10000.jsonl
```

The generator writes only synthetic data, uses exclusive file creation and refuses to overwrite an existing file. Vocabulary indices 0–6 represent media, portfolio, products, travel, education, institution and a deliberately unfamiliar vocabulary.

The first JSONL line is publication metadata: `version`, `name`, `rootId`, `collections`, `edges`, `fields`, `relationshipTypes`, plus optional reviewed `links`. Subsequent lines are `{records, memberships, relationships}`; at most 100 records and 400 memberships/relationships each. Canonical record IDs are shared across chunks; identical repeated records deduplicate and conflicting content for the same ID fails review. This format contains only intended public semantic content: private excerpts/anchors stay in the private source-review system.

Imports stage privately and support up to 10,000 input records, 200 import batches and 128 MiB total read/import I/O. Requests/chunks stay below 600,000 bytes; the transport has a 650,000-byte document ceiling. Each record supports up to 256 assertions and 32 detail blocks. Owner preview is 24 records per page, with explicit truncation to 32 assertions/four blocks per preview record and a 600 KB preview ceiling. Scalar fact/name/summary patches fetch and preserve the full server record. Visitor detail separately pages fields and blocks. Oversized metadata/individual records reject explicitly rather than silently publishing incomplete content.

Latest private review IDs survive Studio navigation/reload. Source conversion, like JSONL reimport, selects the applicable previous review and rejects unfinished import/Apply state. For a site using a v2 manifest, applying source knowledge requires an explicit refreshed collection review → Apply collections → Publish; Studio explains this boundary. Reimport from a prior review performs a three-way correction merge: publisher-edited structural metadata/fields, names/content and assertions stay edited; unchanged data takes fresh source values; rejected memberships remain rejected. Full structure/identity validation runs again. A changed schema/source that makes a preserved correction invalid must be reviewed before publishing. Up to 1,000 record corrections and 1,000 additions/removals of memberships are bounded per review.

Finalize stages immutable record/membership/relationship/index chunks and checks hashes and references. Apply claims the review revision before changing the site draft, and repeated Apply reconciles an already-applied pointer. Concurrent draft changes fail explicitly. Publish verifies the full staged manifest before the existing atomic site publication mutation. Normal draft Undo restores the prior manifest pointer; Publish that restored draft to roll the public revision back. Existing v1 publication rendering remains available. Old visitor sessions/cursors/evidence fail authorization after publication changes; the browser offers reload, with no v2-to-full-v1 fallback.

## Storage and operational boundaries

Local task/review/publication files use private mode 0600 and atomic rename with an in-process CAS queue. Like the existing local demo store, this is a single-process backend. Cloud persistence uses the existing Firebase Admin service boundary and transaction CAS through an injected transport. Tests exercise a mocked transport; no Firestore rules, collections, indexes or production resources were activated or verified live.

Visitor state expires after 30 minutes idle or two hours total. Evidence also binds TTL and dependency revisions; result/cursor stores are bounded and expire after 30 minutes. Process restart invalidates in-memory cursors; refreshing/reopening the query obtains current pages. Durable state remains bounded, but expired local files/private staging orphans are not automatically deleted. No cleanup scheduler, emulator or infrastructure change was introduced. Any production retention/cleanup operation remains separately scoped.

Compiled index admission uses an estimated heap charge (three times serialized compact data), with a 128 MiB single-index and 256 MiB LRU charge ceiling. This is not an exact V8 heap guarantee. The 128 MiB I/O ceiling is measured serialized bytes. Whole-process RSS includes imports, validation clones, staged data, test runner and runtime overhead; it is reported separately below and must not be represented as the compiled-index size. This first implementation materializes the bounded index in one worker; it is not a distributed search service.

The registered demo adapter explicitly prices only the first 24 synthetic fixture records. Its tax rate/delivery fee are fixed test constants, and its 2030 appointment calendar is fake. Real payment, tax calculation, booking, fulfillment, messaging and merchant onboarding are not implemented or activated. Publisher subscription billing is separate and unchanged.
