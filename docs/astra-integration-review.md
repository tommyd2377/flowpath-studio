## Authority through the whole system

| Boundary | Authoritative state and independently checked path |
| --- | --- |
| Upload → extraction | Private stored bytes, MIME/byte bounds and the selected source. `file-validation`, `source-extractors`, `source-adapters`, `website-fetch` and `ocr` enforce supported formats and explicit failure. Local synthetic binaries are real parser input; website/OCR transports are injected mocks. |
| Extraction → evidence → candidate | Exact supplied fragment/page/line/cell anchors in private provenance. `parseSemanticReplyWithProvenance`, `mergeKnowledge` and hash-bound assertion reviews retain support and proposal state. An anchor's existence is **not** proof of entailment. Model envelopes in tests are fixtures, not live extraction output. |
| Publisher correction → Apply | Saved candidate revision, source hash, draft hash and claim. Unsupported pending assertions require decisions; rejected values are removed from the publishable catalog. Identity/source correction histories remain private. Apply atomically updates draft knowledge plus affected media/opening/greeting references; Undo restores the prior draft state. |
| Apply → Publish | `catalogForPublication`, immutable staged public catalogs/media and the current site's publication pointer. Draft edits and staged revisions do not authorize public access. Tests exercise actual local stores/routes plus mocked cloud transactions. |
| Publication → retrieval | `getPublishedKnowledgeSnapshot` supplies source-free approved assertions. Current/as-of selection occurs after this authorization. `retrieveKnowledge` returns bounded entities/facts/relationships/media and explicit unknown, qualified, conflict or omitted states. Legacy projection is a consumer adaptation. |
| Retrieval → operations | `publishedWorkspace` constructs the publication-bound reference registry; the shared reducer validates atomic batches, instance IDs, capacity, base/scene/publication revisions and receipts. Model requests never supply markup, styles, arbitrary URLs or capabilities. |
| Operations → React | `VisitorWorkspace` and `AdaptiveWorkspace` render registered objects, retain independent state and use current-publication media URLs. Focus/return does not replace the open set. A context-limit failure becomes a usable local fallback, with a failed display acknowledgment. |
| React → scene → next request | `captureWorkspaceScene` observes committed DOM, clipping, portals, modal state, order, selection, expansion and scrolling. `acknowledgeWorkspace` waits for mounted/stable output and honors cancellation. `validateVisitorContext` revalidates references/revisions and replaces browser-supplied labels with approved names. Typed and Studio GPT-Live adapters consume this scene; requested layout is not evidence of display. |

The trace combines a real structured-source browser lifecycle, local source/identity/Undo tests, strict mocked semantic-envelope tests, and actual browser context captured on subsequent requests. It does not claim a live model independently discovered the hand-authored graph used in the richer media/relationship fixtures.

## Short offline publisher walkthrough

1. In this checkout, run `nvm use`, then `VOICE_BACKEND=demo VOICE_AI_MODE=demo VOICE_DATA_DIR="$(mktemp -d)" npm run dev`. Open [local Studio](http://127.0.0.1:3220). This creates separate demo data. Stop it with Ctrl+C afterward.
2. Create a general site. Upload [`fixtures/semantic-knowledge/business.txt`](../fixtures/semantic-knowledge/business.txt), choose **Knowledge → Interpret source**, inspect source locations and address/email, then **Apply to draft**.
3. Choose chat or both, set opening visibility to intro-only, optionally choose the three spoken points and a layout/palette, Save and **Publish locally**. Draft changes remain separate until publication.
4. Open the published local site. Ask “Show me the address,” then “Show me the email too.” Close address and verify email remains. Use **Browse published content** to open either again without AI.
5. For the fully seeded photo/relationship/phone/style walkthrough, run `npm run check`, then `npm run test:browser -- tests/browser/adaptive-workspace.spec.ts --output=test-results/adaptive-demo`. This builds synthetic reviewed graphs and generated photos through real local Studio APIs, exercises the full sequence and writes screenshots. Its isolated server exits when the run ends.

For a manual photo continuation, use a synthetic image, apply an album with a reviewed subject association, and Publish locally again. Ask for that explicitly named album, open its first photo, return, and request a map. Unknown coordinates must remain unknown; an example image must not establish a location.

## Residual risks and acceptance boundary

The architecture is locally coherent only within its declared parser, retrieval and workspace bounds. Schemas/reference validation do not establish semantic entailment. Deterministic retrieval has a small lexical vocabulary and a bounded graph; the offline intent parser is not general language understanding. Context omissions/ambiguity must continue to be respected by real models.

Production use still needs live interpretation/voice/OCR quality evaluation, deployed authorization/storage/network verification, operational load/failure testing and physical-device/browser validation. These tasks did not activate commercial billing, domains, background workers or cloud deployment. The independent FlowPath news app and shared GPT-Live transport core are outside this review's changes.

The combined implementation is accepted for hands-on local evaluation with synthetic content. All verification above is local/offline or uses mocked transports. The live plan remains a proposal requiring fresh explicit authorization; no completion claim extends to live model quality or production use. Changes remain uncommitted.
