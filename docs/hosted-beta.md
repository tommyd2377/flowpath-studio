## Implemented candidate

`tester-voice-store.ts` reuses server-only Firestore transactions and the existing `voiceConversations`/global uncertain-session fencing. New `voiceTesterOwners` and `voiceTesterAllowances` records hold free demo time; no wallet credits, price, analytics authority or migration is introduced. Only server-derived identity metadata and a current code grant are admitted. Anonymous intro grants convey no account access; private waveform creation still requires the existing invited account. Active membership and account session plus actual waveform ownership are rechecked transactionally. Founder status is derived from the existing Firebase-verified Google role and actual owner resolution, never request JSON, headers or a client email claim.

The browser's primary WebRTC/data channel handles greeting, conversation and existing Text Box actions. Responses delegation works without a permanent server sideband. The creation response leaves no server socket, timer or continuation running after its HTTP body finishes. The creation response is a bounded stream: it attaches an observer before releasing the SDP answer to the browser. The browser then applies the answer while that HTTP request remains active. A genuine provider `session.started` event starts the meter and schedules the new deadline before confirmation reaches the client. The observer detaches before that HTTP body ends. Heartbeats cannot mark an unconnected call as connected. Failed/canceled setup is closed through the same independent cleanup path. Heartbeats are short same-origin authenticated PATCH requests every ten seconds. A heartbeat extends a liveness lease only after scheduling its independent Cloud Task. An expired/canceled/revoked/changed lease cannot be resurrected; a bounded personal allowance is never extended. Unused superseded deadline tasks acknowledge without scheduling more work. There are no recursive task chains or provider creation retries.

The existing task queue and request-owned cleanup close a **known** provider ID within a bounded request, await matching `session.closed`, and fence settlement by cleanup epoch. Close attaches its receiver before requesting finalization; the browser waits for server-confirmed cleanup. Account changes and page departure invoke the same cleanup. Task names include their deadline, allowing idempotent replacement leases across processes. An identical task conflict is accepted only as an already-existing durable task.

## Limits of the evidence

A deadline task is best effort, not a provider-enforced hard cutoff. Delivery delays, unavailable hosting, exhausted retries, a lost creation response with an unknown provider ID, lost finalization events, storage failure and already-running delegated work can leave exposure. Those outcomes remain uncertain and block replacement admission rather than inventing final usage or releasing time. Closing a browser tab may race provider finalization before the cleanup receiver attaches; event replay is not assumed. No automatic recovery creates another paid session. The owner's accepted remaining OpenAI balance is not treated as instantaneous upstream cutoff.

Knowledge stays creator-private and its existing hosted gate remains closed in this minimal voice candidate. The existing exact-version creation policy/GPT-6 Luna review and 50¢ per-waveform review budget are reused; hosted review must be explicitly configured before the demo gate can open. This does not bypass pending, rejected, manual or changed versions. Public publishing/payment routing is outside this minimal owner/tester demonstration.

A new `/api/demo-access` checks the temporary shared code against a server-only digest, issues a Secure/HttpOnly/SameSite=Strict opaque 24-hour grant, and stores only its hash/expiry. No code or validation digest is shipped to the browser. Exact case/punctuation are required; prior variants are rejected. The server gates readiness, creation-review requests, actual voice reservation and waveform saves. Throttling is transactional across instances: six checks per challenge in ten minutes and sixty globally per minute; rotating a browser challenge cannot bypass the global ceiling. This is temporary shared access, not strong authentication or protection against a determined attacker. Grant/throttle records expire logically; no new TTL/security configuration or credentials are required. Unknown cancellation IDs use a constant-sized actor barrier rather than unbounded tombstone records.

Source activation requires all exact existing project/origin/Firebase checks, `FLOWPATH_HOSTED_TESTER_DEMO=1`, `FLOWPATH_LIVE_ENABLED=1`, `FLOWPATH_TESTER_ALLOWANCE_PERIOD=daily`, creation safety enabled with the approved `conservative-v3` policy, and payments off. An old live flag alone cannot enable the new route. The candidate YAML prepares those activation values. The user authorized this code-gated rollout and explicitly declined paid automated acceptance; deployment results are recorded in firebase-launch.md.
