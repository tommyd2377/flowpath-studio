# Optional Search and explore

Publishers can enable **Content → Search and explore**, choose web image search and interactive maps, restrict search to up to eight public domains, and set a daily allowance of 1–100 search requests. The default is off, including for existing publications. Save changes to the draft and publish explicitly; saving alone does not enable public search. Visitor conversations must also be enabled.

The 2026-09-12 [navigation and web-context extension](search-workspace-improvements.md) adds publisher assistant purpose, a separate opt-in for web additions inside published cards, up to 24 labeled images, expandable source cards, full publication discovery, pointer return and visible-item highlighting. The extension document contains the current code map, pricing proposal and verification boundaries.

Only returned content appears, rendered by `ExternalSearchResults` in `@thevoice/platform-ui`; request handling and validation stay in the host. In the [adaptive workspace](adaptive-workspace-architecture.md), accepted external results are independently addressable objects alongside retained published information, with explicit external provenance. Web results have clickable inline citations and source cards. Image results have numbered thumbnails, source links, an accessible enlarged viewer, Escape dismissal and focus return. External map requests open an attributed OpenStreetMap embed with drag/pan and zoom. Up to six recent result sets are retained; a successful new search rotates out the oldest temporary set while preserving published content. Capacity is checked before a paid request. See [Home and complete website browsing](home-and-published-website.md). Local image/zoom controls work without another search, including after search allowance exhaustion. Close removes that object; explicit Clear releases retained results and their navigation context.

There is no separate public search panel, mode picker or search form. Visitors ask through voice or the main typed composer, which recognizes explicit web searches, requests to find images, maps, and ordinal photo follow-ups such as “Open the second photo.” The continuous voice assistant can request the same views or open an existing image by its displayed ID. Ambiguous voice references require clarification. Voice waits for the browser's navigation acknowledgment before claiming the view was applied. These controls do not open outside tabs automatically; visitors choose source links themselves.

## Providers and boundaries

- **Web and images:** the existing server-side OpenAI Responses integration, using `gpt-5.6-luna`, `store:false`, one required `web_search` tool call and `max_tool_calls:1`. Images use `search_content_types`, `image_settings` and `web_search_call.results`. URLs come from hosted-tool results and citation annotations, not model-written links. Domain filters apply to source pages (image CDNs may use a different domain), and the application filters results again. Unsafe protocols, credentials, explicit IP hosts and local hostnames are rejected. The application never fetches or proxies result pages/images.
- **Maps:** United States/world overviews resolve locally. Other explicitly named regions, cities and landmarks use one bounded structured model response to select an approximate viewport. Unknown or ambiguous locations may return no viewport. The app constructs a fixed OpenStreetMap embed URL from validated numbers. These are approximate area overviews, not geocoded business pins, verified addresses, directions or live inventory. Overview zoom controls reset to the named area; native panning inside the third-party iframe is not observable as exact viewport state by Studio. Multiple destination markers and geocoding are not implemented.
- **External content:** results never become draft or published knowledge and cannot create executable capabilities. Images load directly from source hosts without a referrer; they are not imported into the publisher's media library. Attribution is not a grant of reuse rights. The map background always comes from OpenStreetMap, even when web search is domain-restricted. It is a best-effort service, not a commercial map SLA.
- **Preview:** deterministic synthetic results, labeled illustrations and an offline map placeholder. No model, map-tile or third-party image request occurs in the demo path. Preview does not establish live search quality or provider/model compatibility.

The shared result renderer is hosted by Studio workspace objects, separate from canonical published references. Provider credentials and retrieval orchestration remain server-side. Bounded browser context contains the currently open/focused result, actual selected image or source, retained result IDs, image captions, source titles and overview coordinates; it carries no arbitrary source URLs and grants no authority over published facts. A published object in focus takes precedence over external ordinal follow-ups unless the result is a web addition attached to that object. Ordinary “show a map too” uses reviewed publisher location data; explicit web/United States/world requests can use opted-in external maps.

## Usage and cancellation

Typed and voice searches share a transactionally reserved per-site allowance, default 10/day, plus a global 100/day cap. This is separate from chat/voice generation limits. Request IDs share replay protection with visitor turns; cancelled and failed attempts remain counted. A voice search also consumes its normal voice turn. Known map requests count toward the search-request allowance even though they do not call OpenAI. Manually opening images, switching existing views and zooming do not consume search requests.

Only one Responses request is made per external search or non-preset map lookup, with a 25-second timeout, bounded output and no automatic retries. Voice allows at most one search/navigation tool action followed by one tool-free spoken continuation. Manual interaction, new speech, stopping a search and closing a voice session abort or suppress stale search work. Publication changes are checked before and after retrieval. Existing Stripe-test paid-AI blocking also covers search. No billing rates or credit deductions are added; request caps are not monetary enforcement, and search-tool charges are additional to model tokens.

The integration uses the existing provider configuration. The later [Home and complete website pass](home-and-published-website.md) records three authorized live API tests and a map check; it also fixes citation titles and duplicate source cards caused by tracking links.

## Verification

- `tests/explore.test.ts`: settings, URL/domain filtering, citations, hosted image parsing, single-call limits, map construction, quotas and offline published routes.
- `tests/explore-voice.test.ts`: browser acknowledgment, disabled tools, cancellation and tool-free continuation.
- `tests/browser/search-explore.spec.ts`: publisher controls, image keyboard/focus behavior, typed follow-ups, mobile layout, history, failures, stale responses and a mocked map embed.

Use `npm run check` and, after a build, `npm run test:browser -- tests/browser/search-explore.spec.ts tests/browser/visitor-realtime.spec.ts`. Tests use synthetic data and mocked providers. The bounded live evidence is recorded in [Home and complete website browsing](home-and-published-website.md); broader relevance, cost, latency, microphone behavior and image-host reliability remain separate verification concerns.

### Image intent regression (2026-09-13)

Explicit image searches now send image-specific instructions and `search_content_types: ["image"]`, even when the resolved query is only a subject name such as West Point. Previously the provider received generic text-search instructions with mixed image/text eligibility, which did not reliably communicate the selected image operation. Ordinary web searches retain mixed results when images are enabled. The single-call limit, source validation, publisher opt-in and empty-result handling are unchanged. A mocked transport regression checks the actual outgoing request; it does not prove live image retrieval. Contract reference: [OpenAI image search results](https://developers.openai.com/api/docs/guides/tools-web-search#image-search-results).
