# Website card conditions retain their source owner

The Zabar’s native import assigned some leading product-card badges to the preceding offering. An ornament acquired the following gift wrap’s `FREE SHIPPING` claim; a gift crate and mug acquired the next cards’ `Z-PEAT` label; a deli gift acquired the next card’s `NEW` label. Literal amounts were correct, but the associated conditions were not.

HTML extraction now carries optional exact line ranges for explicit article, list-item or accessible-group cards with one independently priced heading. The existing offering price grammar determines eligibility. Complete-line source matches must account for all identical DOM occurrences; ambiguous matches add no range. Nested wrappers keep the outer eligible card’s text. No badge vocabulary, merchant name, item identity or missing policy is inferred.

Offering extraction respects those ranges when a sibling or ancestor-level offering starts, and retains the owning card’s preheading text. Descendant conditions and following qualifications remain under their existing heading scope. Captured text, raw text, names, amounts, field IDs and exact source offsets remain unchanged. Parser evidence includes the actual owner’s qualification; evidence is still not publisher approval.

The ranges are private, optional extraction metadata, with a 500-range limit and exact-text/order validation. Malformed ranges fail strict extraction; local extraction retains reading evidence and reports that no scoped offerings were accepted. Inputs without ranges retain existing parsing. Stored publications are not rewritten, and unchanged-source deduplication is not bypassed: this change is not a migration or automatic repair of an already applied import.

Validation passed: 79 focused tests, scoped ESLint, TypeScript, a production webpack build, and the independent frozen/adversarial review. The new regression suite fails against the original implementation, including the incorrect delivery claim and its source attribution. Actual patched native import → review → Apply → local composition → local publication → browser details passed six attribution/long-term checks at both 390px and 1440px, with keyboard focus return and no horizontal overflow or page errors.

Verification uses synthetic multi-domain fixtures and the previously captured eleven-page source pack. Focused coverage includes correct sibling ownership, nested wrappers, duplicate cards, monetary policy prose, priced descendant policy headings, external afterwords, unchanged legacy inputs, malformed ranges and exact provenance. Frozen checks retain all 37,767 source characters, 25 offerings and the coffee’s complete 1,289-character conditions block; all 21 homepage tile badges match their actual HTML owners.

The executed local audit separately records the original candidate, explicit field review, application Apply/Publish, local layout proposals, three templates at 1440/390/320px, and actual deterministic chat. The baseline review rejected eight incorrect badge fields and 25 generated `publisher-id` values. The patched publication rejects only those identifiers; its badge fields come from the corrected extractor. No manually authored replacement catalog or paid provider response is used.

Remaining limits include duplicate homepage/detail offerings, synthetic source identifiers, absent demo field bindings, static product-option relationships, and deeper semantic policy interpretation. Cross-product asterisk footnotes and headings that already resemble separate policy offerings are pre-existing limitations outside this fix. The audit’s deterministic chat findings do not establish live model quality; live source/visitor cases are queued for the coordinating ledger owner.
